Mizaj API

Mizaj has three channels. They all use the same mood engine and return the same estimate.

  1. Web app (/): agents search by phone number and see the full customer profile.
  2. Call popup (/popup): a short mood brief that appears when a call comes in, opened by the CTI system or kept open beside the softphone.
  3. API (/api/v1): JSON for CRM, IVR, chat and other systems, plus an embeddable card.

There is no login, by design. Run Mizaj on the agent network or behind your existing gateway or SSO proxy.

Read this first: estimates, not facts

  • Every mood is an estimate (isEstimate: true) built only from interaction evidence: tickets, calls, messages, surveys, visits, follow-ups, incidents and bills. It never uses age, gender, nationality or tenure.
  • If evidence is too thin or too old, the mood is "unknown" and unknownReason says why. Show “Unknown”. Never fill in a default mood.
  • Each estimate includes a confidence level (high / medium / low / none), the reasons behind it, the evidence that points the other way (counterEvidence), lastEvidenceAt and computedAt.
  • Agents can confirm or correct a mood. An active agent observation is returned as agentObservation. display tells you which one to lead with, and display.sourceLabel gives the label to show (“Estimated”, “Agent-reported”, “Agent-confirmed”).
  • Always show the label and the disclaimer next to a mood. Never show the mood as a bare fact.

Quick start

# Mood brief for a caller (what the popup shows)
curl '{{origin}}/api/v1/lookup?phone=90001001'

# Full profile for the web app
curl '{{origin}}/api/v1/customers/C1001'

# Tell Mizaj a call is ringing → open agent screens show the brief
curl -X POST '{{origin}}/api/v1/calls/incoming' \
  -H 'Content-Type: application/json' \
  -d '{"phone":"+968 9000 1001","callId":"CTI-123","agentId":"CC-214"}'

Endpoints

GET/api/v1/lookup?phone=Mood brief by phone number. Use this for IVR, CRM side panels and screen-pops. If no customer matches, returns matched: false with mood unknown.
GET/api/v1/customers?q=Search by full or partial phone number, name or account number. Each result includes its current mood label.
GET/api/v1/customers/{id}Unified profile: services, bills, tickets, calls, messages, feedback, visits, unresolved issues, follow-ups, timeline, mood, suggestions and alerts.
GET/api/v1/customers/{id}/briefThe same brief as /lookup, by customer id.
GET/api/v1/customers/{id}/moodFull estimate with all reasons, plus agent observation, escalation, missed commitments, frustration triggers and suggestions.
GET/api/v1/customers/{id}/timeline?type=Interaction timeline, newest first. Optional type filter: call, message, ticket, feedback, visit, followUp, incident, mood.
POST/api/v1/customers/{id}/mood-feedbackConfirm or correct a mood. Body: {"verdict":"confirmed"} or {"verdict":"corrected","mood":"neutral","note":"…","agent":"Huda (CC-214)"}. Moods: positive, neutral, frustrated, upset.
GET/api/v1/customers/{id}/follow-upsCommitments made to the customer. Each includes an overdue flag.
POST/api/v1/customers/{id}/follow-upsLog a commitment. Body: {"title":"Call back with ETA","dueAt":"2026-10-28T09:00:00Z","owner":"Huda"}.
PATCH/api/v1/follow-ups/{id}Update a follow-up. Body: {"status":"done"} (or "open" / "cancelled").
GET/api/v1/dashboard?days=30Team view: estimated mood mix by week, recurring issues, regions, escalations, missed commitments and agent feedback. days can be 30, 60 or 90.
POST/api/v1/calls/incomingLive CTI webhook. Body: {"phone","callId?","agentId?","queue?"}. Pushes the brief to agent screens listening on /api/v1/events and returns it. If MIZAJ_CTI_KEY is set, send it in the X-Api-Key header.
GET/api/v1/events?agentId=Server-Sent Events stream of incoming-call events. With agentId, a listener receives only calls for that agent, plus calls sent without one.
GET/api/v1/calls/recentThe last 25 call events. Each is tagged mode: "live" (CTI webhook) or "simulated" (demo button).
GET/api/v1/integrationsWhich sources are simulated and which channels are live.
GET/api/v1/metaEngine version, thresholds, mood list and categories.
POST/api/v1/demo/simulate-callDemo only: sends a simulated call, either for {"phone"} or for a random demo customer.
POST/api/v1/demo/resetDemo only: clears agent corrections and follow-up changes, and rebuilds the demo data around the current time.

Screen-pop and embedding

A CTI or softphone can open the popup straight to the caller:

{{origin}}/popup?phone=96890001001

To embed the mood card in another system (CRM side panel, ticket view), add embed=1:

<iframe src="{{origin}}/popup?phone=96890001001&embed=1"
        width="420" height="720" style="border:0" title="Customer mood (Mizaj)"></iframe>

Set MIZAJ_EMBED_ORIGINS (for example https://crm.example.om) to control which sites may frame the card.

How the estimate works

The rules-v1 engine turns each interaction from the last 90 days into a weighted signal. Recent signals count more: their weight halves every 21 days. Open tickets, missed promises and active incidents count in full for as long as they stay open. The signals are added up into a score:

  • −40 or below: Upset · −40 to −12: Frustrated · −12 to +12: Neutral · +12 or above: Positive
  • Fewer than 2 meaningful signals, or total evidence below 8 points: Unknown
  • Confidence rises with the amount, consistency, freshness and strength of the evidence. It is lowered when signals are mixed, or when the most recent interaction points the other way.
  • An agent observation stays in force for 72 hours, or until newer evidence arrives, whichever comes first.

Escalation is flagged when a customer mentions cancelling, switching provider, the regulator, legal action or going public; when two or more commitments are missed; when a ticket is open for more than twice its SLA; after four or more contacts about the same issue in 14 days; or when the customer is upset (estimated with high confidence, or reported by an agent).

Configuration

PORT=3000                     # HTTP port
HOST=0.0.0.0                  # bind address
MIZAJ_CTI_KEY=…               # require X-Api-Key on POST /api/v1/calls/incoming
MIZAJ_CORS_ORIGIN=*           # Access-Control-Allow-Origin for /api
MIZAJ_EMBED_ORIGINS=*         # frame-ancestors for /popup (embedding)
MIZAJ_STATE_FILE=.mizaj/state.json   # where corrections & follow-ups are saved ("" = memory only)
